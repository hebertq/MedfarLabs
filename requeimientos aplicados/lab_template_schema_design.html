El campo value_type en det_lab_exam_template_item define la naturaleza del analito:
numeric
ref_min: 4.5
ref_max: 11.0
unit: "×10³/μL"
Permite rangos por edad/sexo en la tabla de rangos. El resultado se marca fuera de rango automáticamente.
qualitative
ref_options:
["Positivo",
"Negativo",
"Indeterminado"]
Lista cerrada de opciones. El técnico selecciona una. No aplican rangos numéricos.
text
unit: null
ref_min: null
ref_max: null
Campo libre. Usado para observaciones, morfología o descripción de hallazgos.
Lógica de resolución de valores al registrar resultado:
1. Buscar si existe cfg_org_lab_exam_item_config para la organización y el ítem.
2. Si existe y tiene custom_ref_min/max → usar esos valores.
3. Si no existe config propia → buscar en det_lab_exam_template_item_range filtrando por edad y sexo del paciente.
4. Si no hay rango demográfico → usar ref_min/ref_max del ítem base de la plantilla.
5. Si el analito es qualitative → no aplicar lógica numérica, solo validar que el valor esté en ref_options.
Dos actores: el SaaS admin publica plantillas globales. El lab clona y personaliza.
1
SaaS admin crea plantilla global
Crea un registro en mst_lab_exam_template asociado a un servicio de laboratorio. Agrega todos los ítems (analitos) con sus valores de referencia base y rangos demográficos. Cuando está lista, la publica (is_published = TRUE).
2
Laboratorio clona la plantilla
El lab ve las plantillas publicadas y ejecuta "Clonar". El sistema crea un registro en cfg_org_lab_exam_config vinculando su organization_id con la plantilla. También crea un cfg_org_lab_exam_item_config por cada ítem, todos con valores null (hereda de la plantilla).
3
Lab personaliza su configuración
El lab puede: cambiar el nombre de un analito, ajustar sus rangos de referencia, ocultar ítems que no procesa (is_hidden = TRUE), cambiar el orden, o agregar ítems propios (sin vínculo a la plantilla global — template_item_id = NULL).
4
Se recibe la orden de examen
Puede venir desde una orden médica (mst_lab_order con consultation_id) o directamente del lab (consultation_id = NULL). Ambos flujos ya existen.
5
Técnico registra resultados por ítem
El sistema carga los ítems desde la config del lab (o la plantilla si no clonó). El técnico ingresa el valor de cada analito. El sistema evalúa si está dentro del rango y marca is_out_of_range.
6
Se reemplaza el JSONB monolítico actual
La tabla laboratory.det_lab_result actual usa technical_data_json JSONB. Se agrega la tabla det_lab_result_item para resultados estructurados por analito. El JSONB queda para adjuntos externos (PDF del equipo, notas libres).
Qué tablas existentes se extienden o referencian sin romper nada.
